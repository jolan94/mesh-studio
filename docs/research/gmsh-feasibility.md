# Gmsh feasibility: macOS chat-driven STEP → tetrahedral mesh

Research date: 2026-10-06. Baseline: official Gmsh **4.15.2** manual and source release. Planning only: no installation, build, meshing run, desktop packaging, or solver validation. This note covers Gmsh only; the five-option comparison and solver selection belong to the main research.

**Assessment:** Gmsh is a credible candidate for STEP import, controlled tetrahedral meshing, second-order elements, and mesh diagnostics. Arbitrary CAD repair, persistent face identity, solver-ready boundary surfaces, and proprietary desktop distribution remain explicit feasibility gates. “AI chat” should produce a reviewable meshing recipe; it does not establish mesh validity or engineering accuracy.

## Evidence matrix

## Quality is not solution adaptation

Geometric optimization and Jacobian/shape metrics address mesh geometry. They do not demonstrate convergence of displacement, stress, temperature, or another solution quantity. The documented `PostView` route accepts target sizes calculated elsewhere; official [t7.py](https://gitlab.onelab.info/gmsh/gmsh/blob/gmsh_4_15_2/tutorials/python/t7.py#L18) also warns to preserve a model-based background mesh separately while remeshing. The manual explicitly places target-size computation/error estimation outside this meshing step. [Size specification](https://gmsh.info/doc/texinfo/gmsh.html#Specifying-mesh-element-sizes).

**Planning inference:** keep three distinct claims in the UI: CAD repair checks, geometric mesh quality, and solution convergence. A future adaptation loop requires external solution/error data, a validated error→size rule, remeshing, selection transfer, and a quantity-of-interest stopping rule. This note does not select a solver or claim that loop works.

## Python integration and desktop distribution

**Source support:** `api/gmsh.py` loads the native library with `ctypes.CDLL`; Python is a wrapper around compiled Gmsh, not a pure-Python mesher. Initialization precedes API calls and may read system configuration. [Wrapper, L92](https://gitlab.onelab.info/gmsh/gmsh/blob/gmsh_4_15_2/api/gmsh.py#L92), [initialize, L268](https://gitlab.onelab.info/gmsh/gmsh/blob/gmsh_4_15_2/api/gmsh.py#L268). Official releases/SDKs exist for macOS Intel and ARM. [Downloads](https://gmsh.info/#Download).

**Planning inference:** a dedicated Python worker with structured requests, explicit options (`readConfigFiles=False`), logs, and process-level cancellation is a sensible spike. Keep native execution outside the chat/UI process. Architecture compatibility, native dependencies, concurrent jobs, failure isolation, signing/notarization, sandbox access, and clean-machine launch are **unverified**. A worker process provides no automatic licensing exemption.

**Licensing evidence:** Gmsh is GPL **version 2 or later**. Its exception names Netgen, METIS, OpenCASCADE, and ParaView and retains GPL conditions for Gmsh; it is not a blanket proprietary-linking permission. [Exact license](https://gmsh.info/LICENSE.txt). The authors explicitly require a commercial license for integration into distributed closed-source software. [Official licensing statement](https://gmsh.info/#Licensing). Decide GPL-compatible distribution versus a commercial agreement before bundling/linking. Do not assume subprocess separation resolves a combined-product licensing question; dependency notices/source obligations and the chosen distribution architecture need review.

## Concrete spike questions — proposed, not executed

1. **Import/repair:** On clean solid, open-shell, thin-wall, tiny-fillet, mixed-unit, and repeated-instance STEP fixtures, what imports? Does healing retain intended features and acceptable volume/area/dimension changes? What happens to named face selections after rebind?
2. **Meshing:** For Delaunay versus HXT, with one local-refinement recipe, what are failures, runtime, peak memory, element counts, and sizing transitions? After `setOrder(2)` and high-order optimization, are minimum Jacobians positive and curved boundaries represented acceptably?
3. **Boundary/export:** Can a known selected face be recovered as the correct adjacent tet/local-face pairs, with orientation and tet10 midside nodes? Do INP solid sets and optional node sets contain all intended IDs without unintended 2D elements? Can the downstream consumer read the adapter output? Main agent owns solver choice.
4. **Worker/macOS:** Can an explicitly configured headless worker import → mesh → diagnose → export on a clean target Mac, cancel safely, and repeat without configuration/state leakage? Confirm chosen binary architecture, OCCT/CAF/OpenMP capabilities, dependencies, and distributable packaging.
5. **Release gate:** What license permits the intended desktop product and its dependencies? Keep solution-driven adaptation out of the initial claim until an external error estimator and convergence loop are demonstrated.
